## Experimental focused-field live output

Handy can now write native streaming transcription directly into the text control that was focused when recording began. The existing live overlay remains the default. To opt in, enable experimental features and choose **Focused text field** in Advanced settings.

Focused output performs platform-specific target, permission, edit-monitoring, and insertion-route checks on Windows, macOS, and Linux before recording. Supported controls can interleave ordinary typing with speech—for example, speak, type an insertion, then continue speaking—without Handy deleting or replacing either contribution.

Safety takes precedence over continued output. Selection, caret movement, destructive edits, commands, pointer/focus changes, monitor loss, and uncertain insertion results permanently stop that session's live delivery. Once focused output is armed, Handy never performs a late final paste; it preserves partial text and offers History recovery only when the entry was actually saved.

Compatibility is target-specific. Secure fields, active selections, IME composition, controls without sufficient accessibility support, and unsupported auto-submit routes use normal delivery before arming or safely stop after arming. Focus-routed native routes also retain a small, disclosed race between final validation and OS input consumption.

See [Focused-field live output](https://github.com/cjpais/Handy/blob/main/docs/focused-field-live-output.md) for eligibility, native routes, Linux's strict stdin-tool allowlist, coediting rules, permissions, recovery behavior, privacy, and troubleshooting.
